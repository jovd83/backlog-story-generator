# Security Policy

## Supported Versions

Security fixes are applied to the latest version on the `main` branch.
Older tags and forks may not receive coordinated fixes.

## Reporting A Vulnerability

Please do not open a public issue for suspected vulnerabilities.

Report security concerns privately to the maintainer through the contact path documented in [SUPPORT.md](./SUPPORT.md), and include:

- a short description of the issue
- affected files or workflow area
- reproduction steps if available
- impact assessment if known

## Scope

Security reports are most relevant for:

- packaging and release workflow behavior
- repository automation and GitHub workflow misuse
- malicious or unsafe script behavior
- disclosure of secrets or credentials in examples, fixtures, or generated artifacts

Out-of-scope items may still be accepted as normal bugs or documentation issues.
